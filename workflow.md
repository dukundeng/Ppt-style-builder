# PPT Style Builder Workflow

This workflow turns a reference PowerPoint deck into a clear, editable, topic-specific presentation.

The goal is style adaptation, not mechanical copying. Preserve what works in the reference deck and improve what does not.

## 1. Frame The Task

Collect the basic requirements before designing:

- Topic of the new presentation
- Audience, such as classroom, business, academic, report, or speech
- Language
- Target slide count
- Deadline or output format
- Whether the reference deck is a strict template or only a style reference
- Whether the user wants close imitation or a creative adaptation

## 2. Analyze The Reference Deck

Inspect the reference PPT before making design decisions.

Look for:

- Slide count and overall structure
- Cover, contents, divider, body, and closing page patterns
- Section rhythm
- Color palette
- Typography hierarchy
- Image treatment
- Background style
- Recurring shapes, panels, footers, numbers, and line styles
- Weaknesses to avoid, such as overcrowding, low contrast, typos, or repeated layouts

Output a concise style audit before moving on.

## 3. Propose A Visual Direction

Decide what to preserve:

- Tone
- Palette
- Section rhythm
- Title hierarchy
- Image mood
- Signature layout motifs

Decide what to improve:

- Cleaner text hierarchy
- Better spacing
- More varied slide layouts
- Stronger factual visuals
- Topic-specific image choices
- Corrected spelling and typography

Ask for confirmation before writing the final slide outline.

## 4. Research Content And Assets

Use reliable sources for factual content.

For real people, books, companies, places, or products:

- Prefer official websites, publishers, universities, museums, government pages, or reputable encyclopedias.
- Do not invent facts.
- Record sources.
- Avoid fake official assets.

For images:

- Use real verified images when identity matters, such as author portraits, book covers, logos, screenshots, or product images.
- Use generated images only for non-identity atmosphere, such as abstract backgrounds, room scenes, textures, and mood images.
- Do not generate fake portraits of real people unless the user explicitly asks for a fictionalized or non-real image.

## 5. Write The Slide Content First

Draft the full slide outline before building the deck.

For each slide, include:

- Slide number
- Title
- Subtitle, if useful
- Main body copy
- Visual suggestion
- Highlight phrase or callout

Ask the user to confirm the outline before generating or assembling slides.

## 6. Build Editable Slides

Use editable PowerPoint elements whenever possible:

- Text boxes
- Shapes
- Callouts
- Timelines
- Cards
- Tables
- Image layers

Avoid making each slide a single flat screenshot.

Use varied macro layouts:

- Cover with title and visual anchor
- Contents page with numbered sections
- Divider slide with strong section identity
- Text plus image
- Text plus callout rail
- Timeline
- Comparison grid
- Quote slide
- Closing slide

Avoid using the exact same layout for three consecutive slides.

## 7. Visual QA

Render or preview the deck before delivery.

Check:

- Thumbnail readability
- Full-size readability
- Title hierarchy
- Body text spacing
- Image crop quality
- Color contrast
- No text overlap
- No clipping
- No spelling mistakes
- No fake logos, fake covers, fake screenshots, or fake identity images

If an automated checker reports overlap between text and a full-slide background, visually inspect the slide before treating it as a real issue.

## 8. Deliver The Deck

Deliver:

- Final editable `.pptx`
- Short note explaining the style adaptation
- Source summary
- Known limitations, if any

Keep the final explanation concise and artifact-focused.
